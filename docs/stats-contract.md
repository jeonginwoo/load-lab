# 서버 지표 계약 (부하 측정용)

> load-lab 이 서버의 CPU·메모리·접속 수를 읽는 약속. game-hub 의 「게임 입장 계약」처럼, **각 서버가 지킬 것만** 적는다.
> 봇 쪽(지연·메시지 수·전송량)은 서버가 아무것도 하지 않아도 잰다 — 이 계약은 **서버 안에서만 보이는 숫자**를 위한 것.
> 버전 1 (2026-11-24)

## 왜 필요한가

봇은 「메시지가 늦게 온다」까지만 안다. 그것이 서버 CPU 가 꽉 차서인지, 메모리가 새서인지, 네트워크 탓인지는 서버 안의
숫자가 있어야 가른다. 보고서의 핵심 질문 「서버 한 대가 몇 명까지 버티나」(CPU 80% 에 닿는 인원)도 이 숫자가 있어야 답한다.

## 지킬 것

1. **주소** — 게임과 같은 HTTP 서버(같은 호스트·포트)의 `GET /__stats`.
2. **켜기** — 환경 변수로만 켠다. 꺼져 있으면 `/__stats` 는 없는 주소처럼(404 등) 굴고, 게임 동작은 하나도 바뀌지 않는다.
   - `STATS=1` → 토큰 없이 답한다. **로컬 측정 전용.**
   - `STATS_TOKEN=<비밀>` → `?token=<비밀>` 이 정확히 같을 때만 답하고, 아니면 403. **공개 배포에서 켤 때는 반드시 이쪽.**
     (토큰 비교는 시간이 일정한 비교로.)
3. **응답** — `200`, `Content-Type: application/json`, `Cache-Control: no-store`, 본문은 아래 모양의 객체 하나
   (첫 측정 전에는 `null` 도 된다).
4. **CORS 헤더를 주지 않는다** — 읽는 쪽은 브라우저가 아니라 봇 프로세스(Node)다. 다른 웹 페이지가 읽을 이유가 없다.
5. **측정 주기** — 1초마다 재고 마지막 값을 돌려준다(요청마다 재지 않는다 — 봇이 1초마다 묻는다).

### 본문

| 필드 | 필수 | 뜻 |
|---|---|---|
| `conns` | 필수 | 지금 열린 웹소켓 수 (입장 전 연결 포함) |
| `rooms` | 선택 | 사람이 있는 방 수 |
| `cpu` | 선택 | 지난 1초 동안 이 프로세스가 **코어 하나**를 쓴 비율(%). Node 는 JS 를 한 스레드로 돌리므로 100 에 가까우면 포화 |
| `memMb` | 선택 | 프로세스 상주 메모리(RSS, MB) |
| `loopP99Ms` | 선택 | 지난 1초 이벤트 루프 지연 p99(ms) — 서버가 메시지를 바로 처리하지 못하고 밀리는 정도 |

모르는 필드는 load-lab 이 무시한다. 새 숫자가 필요하면 선택 필드로 더하고 이 표에 적는다.

## 서버별 현황

| 서버 | 적용 | 켜는 법 |
|---|---|---|
| game-hub (`jeonginwoo/game-hub`) | ✅ `server/src/load-stats.ts` | `npm run build && STATS=1 npm start` (8080) |
| whiteboard-3d (`jeonginwoo/whiteboard-3d`) | ✅ `server/stats.ts` | `npm run build && STATS=1 npm start` (8787) |
| rinfish (`HYERINI/rinfish`) | ❌ 해당 없음 — 아래 | Cloudflare 대시보드 |

개발 서버(Vite — `npm run dev`)에는 붙이지 않았다. 측정은 배포와 같은 모양(`npm start`)으로 한다.

### Node 서버에 붙이는 법 (예: game-hub)

`statsGate(process.env)` 로 켜졌는지 보고, `startStats(() => ({ conns, rooms }))` 로 1초 측정을 돌리고,
HTTP 요청 처리 맨 앞에서 경로가 `/__stats` 면 `answerStats(...)` 로 답한다. 파일 하나(의존성은 Node 내장만)라
두 저장소가 같은 코드를 복사해 쓴다 — 고칠 때는 둘 다.

### rinfish (Cloudflare Workers + Durable Objects)

이 계약을 그대로 지킬 수 없다 — Workers 는 코드에서 CPU·메모리를 읽을 수 없고, 방마다 다른 객체(Durable Object)라
「서버 전체 접속 수」를 한곳에서 셀 데가 없다. 대신:

- **봇 쪽 숫자**(지연·받은 메시지·거절)는 그대로 잰다 — 방 20명 상한(`full`)과 서버 빈도 제한(움직임 초당 10, 채팅 1초에 1줄)을 봇이 지킨다.
- **서버 쪽 숫자**는 Cloudflare 대시보드의 Workers·Durable Objects 지표(요청 수, CPU 시간, 오류)로 본다. 세부 메뉴는 Cloudflare 문서에서 확인할 것.
- 꼭 필요해지면 혜린과 정해서 방 객체가 `conns`(그 방의 웹소켓 수)만 내주는 주소를 더할 수 있다 — 지금은 하지 않는다.

**배포된 rinfish 에 봇을 붙이기 전에 혜린에게 먼저 말할 것.** Durable Objects 는 요청·시간만큼 요금이 붙을 수 있고,
봇 방도 빈 채로 7일 동안 저장소에 남는다. 로컬(`server` 폴더에서 `npx wrangler dev`)에서 먼저 잰다.
